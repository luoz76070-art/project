# Codex运行中直接引导与排队修正

## 现象与依据

用户反馈运行中输入清空、原任务没有收到。手机截图显示“排队1 · 测试发送一次”，之后选中了“引导当前任务”。只读核对同会话的私有待发记录：该条仍为waiting。原UI两个按钮只设置下一次发送方式，不会发送草稿或转换既有队列；首次默认queue，所以原任务没有这条引导。此证据能确认该条实际入队，不能据此声称真实引导路径已通过。

当前在线网关instanceId在检查时为`2c7a0b66-dfeb-49fe-b9fc-b6be2f2ed80a`，Tunnel connected。本轮不转换、取消或重发真实待发项，也不启动真实模型或审批。

## 修正

手机运行中的“引导发送／排队发送”直接提交当前草稿；箭头与快捷键默认排队，旁边有明确说明。请求捕获点击时的mode与guard，空闲显式start；所有发送入口共用提交锁，避免双击。网关原有native/FIFO契约保持，已有待发项不会变为引导。

原生发送保留输入与附件，HTTP/SSE共用按clientMessageId匹配的确认处理，完整正文与附件仍相同时才清空。发送期间的新编辑保留。ACK与未知结果显示待确认、保留输入并禁止重复提交，不虚构已接收气泡。入队只显示待发；桌面确认引导后才显示已接收。已确认记录优先于迟到HTTP错误，旧HTTP确认不清其他提交标识。可见反馈独立于运行状态，取消待发也显示结果。
