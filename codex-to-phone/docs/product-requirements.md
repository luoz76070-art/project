# 产品需求规格

更新时间：2026-05-12

## 一句话目标

做一个手机上的 Codex Desktop 工作台：手机端能像桌面端一样选择会话窗口、查看历史、定位最新消息、继续实时对话、查看工具执行和处理审批。

## 用户已经明确提出的要求

- 最终必须可落地使用，优先输出可安装 APK。
- 不破坏当前 Codex、系统、环境、配置和已有工作流。
- 电脑仍然运行 Codex，手机作为移动客户端接入。
- 手机端不是远程桌面画面，也不是只连接 Codex CLI。
- 手机端要能同步桌面端 Codex 内容，随时随地开发使用。
- UI 不能只是简单测试页，要接近 Codex Desktop 的工作界面。
- 需要类似分屏效果，可以选择聊天窗口进行实时对话。
- 必须支持多线程工作台：切换线程后仍能向对应线程发送消息，每个线程保留自己的草稿、消息缓存和发送状态。
- 必须区分桌面端已有线程和手机端新建线程，不能让用户误以为所有手机新建窗口都会自动出现在电脑端当前 Codex 窗口。
- 点开一个窗口后自动定位到最新位置。
- 可以上拉查找历史记录。
- UI 需要具备 iOS 26 毛玻璃质感。
- 需要白天和黑夜效果。
- 交互必须细致，不能只是简单按钮点击。
- 每一步要稳步推进，做烟测和实测。
- 后期记录文件放在本项目目录。

## 工程侧补全的核心需求

### 1. 工作台主界面

主界面应是 Codex 工作台，而不是连接配置页。

必须包含：

- 会话列表区域：显示最近 Codex 线程、项目路径、更新时间、状态。
- 聊天详情区域：显示选中线程的完整消息流。
- 输入区：固定在底部，支持给当前线程继续发送消息。
- 状态区：显示连接状态、当前 turn 状态、是否等待审批。
- 设置入口：连接地址、Token、诊断、主题、日志都收进设置面板。

### 2. 线程列表

必须支持：

- 最近线程按更新时间排序。
- 搜索线程标题、路径、内容摘要。
- 展示项目路径或来源。
- 展示来源标签：桌面线程、手机/Relay 线程、CLI 线程。
- 当前选中线程高亮。
- 下拉刷新或显式刷新。
- 空状态和失败状态。
- 线程较多时保持滚动性能。
- 支持固定显示方式：自动、左侧固定、顶部固定、抽屉。

后续增强：

- 收藏线程。
- 按项目分组。
- 归档/隐藏线程。
- 最近打开记录。

### 3. 聊天窗口

必须支持：

- 打开线程后自动滚动到最新消息。
- 用户主动上拉后保持浏览位置，不强行拉回底部。
- 新消息到达时，如果用户在底部则自动跟随；如果用户在历史位置则显示“有新消息”提示。
- 消息按角色区分：用户、Codex、工具、系统、审批。
- 工具输出使用可折叠块，长输出不能撑爆页面。
- 支持复制消息、复制代码块、复制命令输出。
- 支持重新加载当前线程。

后续增强：

- 消息内代码高亮。
- Markdown 渲染。
- 文件引用跳转。
- 图片附件预览。

### 4. 实时对话

必须支持：

- 在已有线程中继续发送消息。
- 新建线程发送消息。
- 手机端必须能实时看到正在运行中的 turn 进度，包括思考、文本增量、命令执行、文件修改、审批等待和完成状态。
- 手机端必须能中断当前 turn。第一阶段至少能中断由手机/Relay 发起的 turn；最终目标是能中断桌面端当前正在运行的同一 turn。
- 手机端必须能在运行中的 turn 上继续追加指令或 steer，而不是只能等整轮结束。
- 手机端必须能在电脑端 Codex 正在施工时启动新任务，但要有并发风险提示和项目/工作区锁，避免两个 turn 同时改同一目录造成冲突。
- 切换线程后仍能发送到当前选中的线程。
- 每个线程独立保存草稿。
- 每个线程独立显示发送中/失败/完成。
- 新建线程必须使用明确的 cwd，不能默认跑到 Relay 自己的 `apps/relay` 目录。
- 显示发送中、思考中、执行中、完成、失败。
- 支持中断当前 turn。
- Relay 与 Codex app-server 的连接断开时能恢复或提示重连。

桌面同步口径：

- 续写桌面端已有 `vscode` 来源线程，是当前最接近“桌面同步”的模式。
- 手机新建线程会落盘到 `~/.codex`，但 Desktop UI 是否自动出现在当前窗口取决于 Desktop 自身刷新和项目筛选。
- 手机端必须展示线程来源、cwd、threadId，并提供复制定位信息。
- 当前已接入 Desktop Electron IPC owner/follower 通道，可对 Desktop 拥有的线程发送、引导和打断；但不能宣称已经附加到 Desktop stdio app-server 子进程。
- 如果 Desktop 当前窗口没有拥有该线程，IPC 可能返回 `no-client-found`，手机端必须显示清楚错误。

当前已实现但需要升级：

- 当前 `/api/live/messages` 是请求-等待-返回模式。
- 下一阶段需要升级为 WebSocket 或 SSE 事件流，实时显示 `agentMessageDelta`、工具输出、turn 状态。

实时控制分层：

- Relay 自己启动的 Codex app-server turn：协议已支持实时进度、steer、interrupt，必须优先落地。
- Codex Desktop 当前窗口正在运行的 turn：当前路线为 Desktop IPC `thread-follower-*`，手机端已接入首版，仍需真机验证忙碌 turn 的引导和打断。
- 文件落盘轮询仍作为观看和恢复兜底；控制必须走 Desktop IPC 或 Relay app-server 协议，不能只靠写文件。

电脑端显现要求：

- 用户从手机新建线程后，需要尽量让电脑端 Codex 能定位/显现该线程。
- 第一阶段必须提供清晰定位信息：threadId、cwd、rolloutPath、来源、创建时间，并支持一键复制。
- 第二阶段增加“发送到电脑端/桌面打开”能力：如果 Codex Desktop 有 deep link、控制 socket、远程控制或 app-server proxy，可通过官方/稳定通道打开对应线程。
- 如果 Desktop UI 不支持外部打开线程，手机端必须明确提示“线程已落盘但桌面端可能需要刷新、搜索或从同一项目重新打开”。

2026-05-12 首版工作台 UI 已实现：

- 侧栏线程选择。
- 聊天详情。
- 底部输入区。
- 设置面板。
- 白天/黑夜/系统主题。
- 工具输出可折叠展示。

### 5. 工具输出和审批

必须支持：

- 命令执行卡片：命令、cwd、状态、输出、退出码、耗时。
- 文件修改卡片：文件路径、diff 摘要、展开查看。
- 审批弹窗：approve / deny，显示风险信息。
- 危险操作二次确认。

安全底线：

- 不默认永久放行。
- 不提供无提示的危险操作。
- 遇到无法识别的审批请求，默认阻断并提示回桌面处理。

### 6. 连接和安全

必须支持：

- 保存 Relay 地址和 Token。
- Token 隐藏/显示。
- 连接诊断，但不能占据主界面。
- 清晰区分：Relay 不通、Token 错、Codex app-server 不可用、网络超时。
- 局域网使用 HTTP 可用，远程使用 Tailscale 或其他安全隧道。

后续增强：

- 二维码配对。
- Token 轮换。
- 设备列表。
- 只监听 Tailscale IP。

### 7. 主题和视觉

必须支持：

- 白天主题。
- 黑夜主题。
- 跟随系统主题。
- 手动切换主题。
- 毛玻璃层级、半透明侧栏、动态阴影、细边框。
- 手机竖屏、横屏、平板适配。
- 玻璃质感需要有边缘高光、背景透射、层级阴影、细微反射，不只是半透明深色块。
- 线程切换、设置抽屉、侧栏固定/展开、新消息出现、发送状态都需要有动效。

### 8. 成品交付

必须输出：

- 可安装 APK。
- Windows Relay 启动方式。
- 测试说明。
- 当前限制说明。
- 实测记录。

可选备选入口：

- 微信/企业微信/Telegram 接口。
- PWA。
- Tailscale 内网访问 Web 版。

## 非目标

- 不做桌面画面同步。
- 不改官方 Codex Desktop 安装文件。
- 不裸露公网端口。
- 不把手机端做成一次性调试工具。
- 不只支持新建 CLI 会话。
- 不用连接诊断页面替代主产品体验。

## 第一版验收口径

第一版不要求完全复制桌面端所有能力，但必须做到：

- 打开 App 后呈现工作台界面。
- 能看到 Codex Desktop 历史线程列表。
- 点线程进入聊天详情，并自动定位到底部最新消息。
- 能上拉看历史。
- 能在当前线程发送消息并收到回复。
- 能看到基本工具输出。
- 连接配置隐藏在设置里。
- 白天/黑夜主题可用。
- APK 可安装并完成真机测试。
