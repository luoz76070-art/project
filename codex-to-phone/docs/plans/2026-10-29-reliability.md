# 手机同步与输入可靠性优化计划

状态：阶段一至五的源码实施与隔离验证已完成（2026-10-30）；未发布、Android真机待验。来源：[2026-10-29代码复审](../audits/2026-10-29/code-review.md)。证据：[阶段一、二](../audits/2026-10-29/reliability-fix.md)、[阶段三](../audits/2026-10-29/prompt-visibility.md)、[阶段四](../audits/2026-10-29/compact-diagnostics.md)、[阶段五](../audits/2026-10-30/maintenance-boundaries.md)。

## 目标

让手机在断线重连、连续任务、长历史和重开应用时，保留正确的当前任务状态及未发送输入，并能用短小证据解释版本与显示差异。

本计划不调整模型供应商、不重写UI，不自动发布、操作真实任务或做Git写入。此前真机重复问题仍未解决，不能将这次独立缺陷修复代替原问题的真机验收。

## 阶段一：修复状态回退（R1，源码与隔离验证完成）

范围：Codex轮询/SSE状态写入与订阅清理；提取必要的状态更新函数便于真实调用点测试。

- 使用独立轮询代次和AbortController；取消后的迟到结果在写入前丢弃。
- 校验请求所属thread/turn/generation，防止旧turn回包覆盖新turn。
- 同generation的cursor单调前进；明确reset/文件轮换允许切换基线。
- 保持既有发送确认和不自动重试写入的语义。

验收：旧turn完成回包不能清空新turn；cursor300之后收到旧200仍保持300；SSE恢复/切线程/切Agent/切连接后旧回包不改新状态；有效reset仍可读取新日志；现有369后端、84手机及消息回归通过。先在延迟网络夹具复现，再接真机可行的只读恢复测试。

## 阶段二：保护草稿与待确认输入（R2，源码与隔离验证完成）

范围：Codex本地缓存的存储边界与迁移，不改变服务端消息身份。

- 草稿/待确认身份独立保存，不参与普通历史LRU淘汰。
- 正文缓存按总字节预算和最近访问淘汰；配额失败优先保全输入并明确提示。
- 迁移读取旧缓存；对有损、超额情况给出可恢复结果，避免清空整个域的存储。

验收：6线程×120条×约8KiB记录的容量场景仍能重开恢复新草稿；25个有草稿线程均可恢复；待确认clientMessageId保留；跨连接隔离、旧缓存迁移及真正同文多次发送保持；Chrome配额测试和Android实机结果分别记录。

## 阶段三：修复正常提示词误过滤（R3，源码与隔离验证完成）

范围：Relay历史投影、Desktop/app-server实时投影和手机消息筛选。

- 对自动注入上下文采用明确来源证据，正常用户正文不因通用角色提示词前缀被隐藏。
- 明确来源缺失时的兼容规则，并同时覆盖本地占位、实时消息与落盘历史。

验收：`You are a code reviewer. Check this module.`发送后、历史回放、重开均保留；已确认的系统注入上下文继续隐藏；普通英文/中文、多次同文、含附件输入均不过滤或误合并。

## 阶段四：补齐小型诊断（R4，源码与隔离验证完成）

范围：用户主动触发的诊断摘要与网关限长事件记录。

- 摘要包含原生APK版本、实际Web构建标识、活动热更新、网关构建标识和缓存schema。
- 记录连接代次及少量断开/恢复原因；DOM气泡与消息身份可对应。
- 默认复制摘要硬上限2048 UTF-8字节，完整报告保存文件且不超过65536字节；不含正文、密钥或完整会话。

验收：能区分“安装了新APK但活动Web资源不同”；能区分“两个运行态消息”和“一个消息对应两个可见节点”；模拟断开/恢复能还原顺序；摘要体积、脱敏、失败重试都有断言。取得用户当前原页面证据后，才安排双气泡问题的对应修复。

## 阶段五：整理维护边界（R5，源码与本地验证完成）

范围：App内部状态更新器/连接hook和统一验证入口，保持产品行为。

- 先把阶段一涉及的状态更新器移为可直接导入的模块，逐步减少从App提取源码的测试。
- 将类型检查、隔离测试、构建和Android lint兼容运行方式整理为正式脚本；不要依赖被忽略的output目录作为唯一入口。
- JS/TS lint从明确可执行的规则开始，避免机械改写现有无关代码。

验收：关键状态回归直接导入生产模块，旧调用点仍覆盖；统一入口在记录的工具链上可重跑；现有测试与构建保持通过，Android lint无Error/Fatal；不以文件行数下降代替功能验收。
