# Codex同步与发送能力修复候选

状态：2026-11-04本轮原会话按需加载修复与真机验收完成。后端13项新增回归、手机126/后端403及第二个冷会话实际加载通过；新版固定网关已上线，两端健康/列表及四会话控制恢复。用户确认APK38正文与草稿按钮正常，实际消息由手机发送，重开后输入和完整回复各一次。详见[实施记录](../audits/2026-11-04/codex-cold-thread-recovery.md)。手机失败原因提示与连接分层表达仍列第3项，未作为已交付UI。第2、3项为下一轮候选，等待用户选择。

## 1. 未加载会话的可控状态

目标：手机打开本地历史会话时获得可解释的状态；支持的原会话可按需加载并取得真实控制令牌，失败显示明确原因，不能只有灰按钮或无限“同步中”。

先核对当前宿主支持的官方原会话加载/恢复接口，以及是否改变线程、配置或启动任务。仅在确认不会启动模型、不会创建另一个线程后接入；没有稳定接口时明确标记需先在桌面打开，不能伪造canSend或自动改用CLI。按线程去重进行中加载，限定超时，用户切走后释放跟随引用；未知发送结果锁保持。

验收：合成无owner→加载→原owner→首帧的完整时序；重复打开不重复加载；加载失败/超时明确呈现；已加载线程、运行中引导/排队、未知提交保持。用户指定原空闲会话再验手机按钮恢复，实际发送由用户完成并确认原会话一次输入。

## 2. 列表活动时间

依据：[只读排查](../audits/2026-11-03/codex-connection.md)中两端recent28/all123一致、桌面30个样本均在all列表，但15个被recent筛除，且桌面元数据与日志时间存在差异；尚未证明近期真实对话丢失。

目标：近30天范围与用户理解一致，全部时间可按需查看，不误把连接正常但被筛选的记录当作丢失。

先使用用户指定缺失样本确认是否存在近30天真实对话，再比较桌面updated_at/recency_at、索引与rollout时间，明确采用哪一字段。不直接以迁移或改名时间替代消息时间。若确认需要桌面权威摘要，优先稳定读取接口；本地库只能以只读、版本兼容、有界缓存和文件索引回退方式接入，不扫描全部消息正文。

验收：30天边界、新对话激活旧线程、仅修改名称/项目、全量分页、冷启动及缓存失效；本地/公网相同ID集合；手机“查看更早会话”能找到用户指定历史项。

## 3. 连接检查表达

依据：本轮已复现HTTP/Tunnel/IPC健康、历史可读，但未加载会话没有控制快照，手机发送长期置灰；后端现有following诊断状态尚未在APK38显示具体原因。

目标：基础联网、实时流和当前会话可控状态分开展示，不再让“连接成功”暗示任意会话都可发送。

验收：HTTP200但无owner、SSE429、IPC断开、未知提交及正常可控分别显示准确状态；诊断只在用户请求时运行，不主动加载全部会话或提交模型任务。

后续建议目标：让用户能判断会话被时间范围筛除还是控制状态未就绪。先验证第2项活动时间语义，再按证据决定是否修改筛选；第3项与状态提示一起交付。两项均以以上验收标准及本地/公网一致为完成依据，需用户选择后才启动。涉及网关/APK时按现有候选、检查、preview及回退流程执行，不将能力检查当真机发送成功。
