# v1.1-upload 版本记录

更新时间：2026-05-13

## 版本产物

- Windows 独立包：`安装文件-v1.1-upload`
- Windows 独立包压缩包：`安装文件-v1.1-upload.zip`
- Android APK：`安装文件-v1.1-upload\apk\mobile-codex-1.1-upload-debug.apk`
- 开发输出 APK：`dist-apk\mobile-codex-1.1-upload-debug.apk`

本版本不覆盖旧的 `安装文件` 和旧 APK。以后继续按 `安装文件-vX.Y-name`、`mobile-codex-X.Y-name-debug.apk` 的方式保留多个版本。

## 新增功能

- 手机输入区新增上传按钮，可从手机选择文件上传到电脑。
- Relay 新增 `POST /api/uploads`，上传文件保存到默认工作目录下的 `mobile-uploads`。
- 上传成功后，手机会把电脑端保存路径追加到当前输入草稿，方便继续让 Codex 处理该文件。
- Relay 新增 `GET /api/status`，返回 Relay、Codex Home、默认工作目录、上传目录、Live、Desktop Control、当前桌面线程等状态。
- 手机设置页新增电脑状态区，可查看上传目录和运行状态。
- 手机端新增轻量 keepalive：App 打开时每 60 秒检查 `/health`，切回前台时刷新状态。

## 后台守护

- 新增 `MobileCodexWatchdog.exe`。
- 新版 Manager 勾选“启用自启”时，优先把 Windows 开机启动项指向 Watchdog。
- Watchdog 每 30 秒检查本机 Relay `/health`。
- 如果 Relay 退出、崩溃或电脑重启后尚未启动，Watchdog 会自动启动 `MobileCodexRelay.exe`。
- Watchdog 已兼容 `0.0.0.0`、`::`、具体 IPv4、具体 IPv6 的本机健康检查，避免 IPv6 配置下误判掉线。

边界说明：电脑端可以通过 Watchdog 长期保持 Relay 在线；手机 App 如果被 Android 完全关闭或系统杀后台，不能保证仍维持一个常驻连接。实际使用上，电脑端 Relay 会一直守着，手机重新打开 App 后会自动重新连接。若以后要手机也在完全关闭后常驻，需要做 Android Foreground Service，并显示系统常驻通知。

## 第二台电脑落地

最简单复制：

- 复制 `安装文件-v1.1-upload` 整个文件夹，或复制 `安装文件-v1.1-upload.zip` 后解压。
- 第二台电脑必须已经安装并登录 Codex Desktop。
- 打开 `MobileCodexManager.exe`，确认 `CODEX_HOME` 指向第二台电脑当前用户的 `.codex`。
- 确认默认工作目录是这台电脑上真实存在的目录。
- 保存配置，启动 Relay。
- 如果要开机自动保持在线，重新点一次“启用自启”。
- 手机安装 `apk\mobile-codex-1.1-upload-debug.apk`，填写第二台电脑显示的 Endpoint 和 Token。

## 重要修复

- 修复 Windows 下 Codex executable 是 `codex.cmd` 时直接 spawn 可能出现 `spawn EINVAL` 的问题。
- Android 打包脚本补齐 JDK 21、Android SDK、Gradle 临时构建路径处理。
- Android 工程补齐基础资源：应用名、主题、图标、`file_paths.xml`，避免新 APK 构建缺资源失败。
- 打包脚本不再输出/覆盖通用 `mobile-codex-debug.apk`，只输出带版本号 APK。
