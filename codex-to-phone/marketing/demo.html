Project Story

我把 Codex 的当前工作流搬到了手机上

电脑继续运行 Codex Desktop，手机只负责看进度、发指令、收结果。 它不是远程桌面，也不是另一个聊天机器人。

“人离开电脑以后，还能不能知道 Codex 在干什么，甚至继续给它发指令？”

✓
绑定当前 Mac 上的 Codex Desktop 工作流
✓
手机端显示输入与文本结果，隐藏工具噪音
✓
通过公网 Broker 支持异地和蜂窝网络
旁白：先讲一个真实痛点，Codex 在电脑上跑着，人一走开就只能猜。
Problem

用户要的不是远程桌面，而是当前会话的遥控器

手机应该连到正在发生的本机工作流，而不是复制整个桌面画面，也不是另开一个没有上下文的手机聊天。

1

离开电脑后失去进度感

Codex 是在读文件、跑测试、等授权，还是已经写完结果，手机上都看不到。

2

远程桌面太重

整屏投过来不是移动工作台，它只是把桌面缩小，输入和阅读都别扭。

3

普通手机聊天没有本机上下文

另开一个聊天机器人不知道电脑上的仓库、会话、工具执行和当前任务状态。

不要做成

×
远程桌面画面同步
×
历史聊天归档器
×
后台影子 Codex

应该做成

✓
当前 Codex Desktop 会话的移动控制台
✓
从手机看结果、发输入、继续推进
✓
跨网络、短链路、少噪音
旁白：这个项目的边界很重要，手机不是替代电脑，是拽住电脑上那条正在跑的工作流。
Phase 0

第一版：扫码网页证明链路可行

电脑启动 bridge，生成二维码，手机扫码打开网页。它解决了“能不能看见当前会话”的验证问题。

✓
PC 到手机的会话可见性成立
✓
短 token 与 session 绑定可限制单会话
✓
启动时只回填上一轮，避免历史污染
$ start codex-to-phone
binding current thread...
pairing token created
QR ready for one session

Limit: 临时域名、浏览器体验、局域网限制
旁白：扫码版不是产品形态，但它给了第一个确定性，当前 Codex 会话可以被手机看到。
Key Finding

后台 app-server 能生成回复，也能写到同一个 thread，但 Desktop 当前窗口不会显示实时过程。

后台 app-server 路线

先打开目标 thread，再把手机文本提交到 Codex Desktop 输入框，让当前窗口自己发起 turn。

Mobile Codex Input.app
PC 和手机同步看到过程
旁白：这是整个项目最关键的工程判断，目标不是制造一个影子 Codex，而是控制当前 Desktop 会话。
Remote Architecture

远程场景不能靠同一 Wi-Fi，正式路径是 Broker

Mac 和 Android 都主动访问公网 Broker。Broker 只转发，不保存完整会话，也不变成第二个 Codex。

Android Mobile App

查看会话、发送输入、上传附件、检查更新

Public Broker

HTTPS/WSS 转发，匹配 relayId，不保存历史

Mac Relay App

读取 Codex 会话，注入手机输入，保持隧道

Desktop Codex

当前窗口执行任务，保留本机安全边界

示例 Endpoint：https://broker.example.com/r/my-mac。 生产部署时用户可以替换成自己的域名和 relayId。

旁白：Broker 是长期远距离使用的基础，PC 不开放端口，手机也不需要在同一个网络。

Reality Check

当前版本可用，但不装作完美

这类工具最容易的问题是过度承诺。真实边界要写清楚，用户才知道怎么部署和排错。

!

Mac 输入依赖辅助功能

`Mobile Codex Input.app` 需要 Accessibility 权限，Codex Desktop 也需要能聚焦到目标线程。

W

Broker 需要自己维护

公网使用依赖 HTTPS/WSS、反向代理和稳定重连；局域网只是验证路线。

T

不是底层 token 流

输出来自 Desktop 状态与会话 tail，长文本仍可能按块同步，再由前端模拟平滑展示。

旁白：承认限制不是削弱产品，而是让项目看起来更可信，也更方便别人复现。
