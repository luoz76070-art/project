# Kelivo 风格迁移与整合可行性复核

## Goal

复核统一 Kelivo 风格及双独立功能的可行性，先迁移现有远控的样式、导航、聊天、设置与 Agent 页面，并用隔离浏览器验证保留原控制行为。

## Requirements

- 原始整合目标保持：Kelivo 完整功能与电脑远控可各自独立使用，另增可选任务交接，全 App 统一 Kelivo 风格。
- 本轮交付是可行性复核及现有 codex-to-phone 的首轮视觉迁移，不把整合 Kelivo 功能或双运行时兼容宣称为已完成。
- 以固定 Kelivo v1.3.4 的默认浅深配色、真实仓库截图、输入框和设置源码建立可复查参考。
- 迁移现有聊天、会话抽屉、输入区、工具/问答/审批、设置/配对及 Agent 页面，保留发送、排队、停止、附件、语音等原有入口与权限判断。
- 只调整展示与样式；不改变会话路由、原控制协议、凭证、缓存和线上服务；不增加未实现的 AI 助手按钮。
- 隔离浏览器验收使用现有合成服务，不读取真实 Codex 会话、不提交真实模型任务，不发布或覆盖安装手机。

## Acceptance Criteria

- [x] 可行性记录区分：当前 UI 迁移可实施、双独立入口产品结构可实现、全功能运行时整合尚待原生验证。
- [x] 记录 Kelivo 固定版本截图与源码中的色值/组件基准；有本项目前后对照。
- [x] 聊天、侧栏、输入区、工具/问答/审批、设置及 Agent 页面采用统一浅深配色与组件风格。
- [x] 360/390/430px、150% 字号及小高度下无横向溢出，主要操作至少 44px 且可命中；分屏与桌面布局保持可用。
- [x] 浏览器核对复制、过程折叠、草稿/会话切换、设置、发送/排队/停止和语音面板；真实模型及 Android 系统操作另行验收。
- [x] lint、类型检查、生产构建、手机与消息回归通过；记录未运行的原生检查和实际限制。

## Notes

- 用户已授权在可行时先尝试现有界面迁移，不再为模板门重复请求批准。
- 保留工作区既有修改和其他任务；不创建分支，不自动推送或发布。按本地版本流程核对提交范围。
