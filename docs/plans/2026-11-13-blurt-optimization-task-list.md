定稿：2026-11-13（第 3 版，替换同日初版）。
依据：Blurt main 6d9eb4d（1.0.21，MIT）；docs/plans/2026-11-12-blurt-mobicodex-optimization.md；11-13 清单的源码核对（抽查仍成立）。
规模：S ≤ 1 天，M 2–3 天，L ≥ 1 周（单人，不含真机验收）。派给：按 Codex 模型分配表；审查由 Claude 做。

## 已定的决定
- 里程碑 A 最先做；手机端不需要切换模型（M1 取消）。
- applicationId 等正式版一次性改（B3）。
- CC Desk 采用 IPC 控制桌面端（和 Codex 一样），不做浏览器访问内嵌（原 C1 取消）。
- Codex 并发上限 2 个会话。
- 任务实现派给 GPT（桌面端 Codex），Claude 写说明、审查、跑测试。
- Logo 定为 A1“墨夜琥珀”：墨色渐变底 #363B46→#101216（左上微亮，防止在深色壁纸上糊掉）、米白 M #F5F1EA、琥珀点 #F59E0B。矢量源文件（圆角图标、自适应前景/背景/单色层、浅底单标）随 B4 提交进仓库。
- UI 审查用临时配对的无头浏览器截图完成（11-13，配对用完即撤销），结论见 U 系列。
- GitHub 流程（E1）已同意并接好。
- B4（换新 logo）提前到 P0，与 B1 一起做，图标资源只改一次。

## UI 审美（U 系列，P0 完成后开始）
11-13 截图审查的总体判断：结构已经齐全，问题在“灰、散、技术味”。全屏几乎只有灰阶，强调色只出现在零星几处；每条消息都重复头像、名字、时间和一整行复制按钮，纵向很松；界面上直接出现 Relay、token、检测、Pair phone 这类术语。
注意：在 Kelivo 宿主里，网页工作台的颜色由 Flutter 下发（apps/kelivo/lib/features/product/product_shell.dart 的 productPalette），所以换配色要改 Kelivo 的 palettes.dart 默认调色板，网页 CSS 变量只是非宿主时的默认值，两边取同一套值。
