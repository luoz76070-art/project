# Boundaries
Capture image parser is pure and bounded; no codec dependency. Dedicated managed store uses private atomic manifests and immutable image files under mobile-uploads/captures. WorkItem stores capture metadata in its existing atomic snapshot; capture asset ownership verified by server. Deleted items retain receipt/tombstone and asset reference metadata for W6; list/get hide them.
Web panel sits above both agent/Codex workspaces, uses existing authenticated transport and VoiceInput in raw capture mode. Memory-only frozen transactions support explicit same-request retries; no background synchronization or persistent drafts. Canvas makes a separate preview after Relay validates and strips source metadata. File selection and ASR never send chat messages.

## Implemented API and boundaries
- POST /api/uploads: legacy bodies unchanged; capture body adds purpose=capture, assetId, captureId, role=original|preview, originalAssetId (null for originals), mimeType, fileName, dataBase64. Result upload is CaptureAsset. Same ID and exact request returns persisted receipt; changed content/owner/metadata returns 409.
- GET /api/capture-assets/:id: authenticated binary image, no-store/nosniff; ?encoding=base64 returns {asset,dataBase64} for the existing Capacitor-compatible JSON transport. All paired workspace devices share read access. A new card can bind only the creating device's uploaded assets.
- POST /api/work-items: normal W1 unchanged. Capture additionally requires current storeId and capture={id,mode,createdAt,assetIds,rawTranscript}; assets must be empty, server resolves originals and generates source.kind=capture. Previews appear only in capture.assetIds, so the existing 16-original-attachment limit remains intact.
- PATCH /api/work-items/:uid: mutationId + expectedRevision and editable fields; capture/source/original evidence cannot be overwritten.
- DELETE /api/work-items/:uid: mutationId + expectedRevision; only never-dispatched todo capture cards. Tombstones retain identity, receipt, original metadata and timestamp; repeated exact delete succeeds, stale create/updates get 410. work-item.deleted SSE contains identity/revisions only. source=capture is a list filter for the small capture panel, not a W5 board.
- Managed assets: immutable file + receipt.json within an atomic renamed UUID directory under mobile-uploads/captures; 25MiB/image, 40MP, edge16384, 16 originals plus up to16 previews, 100MiB per capture including previews, 1GiB data / 32000 assets workspace cap. Invalid/corrupt managed storage fails closed. Guard before publish plus D2 response guard preserves revocation semantics.
- W6 uses WorkItem.capture.assetIds and tombstone timestamps as reference truth. No cleanup or TTL implemented: abandoned uploads and deleted cards still occupy capacity, explicitly refuse when full. Original legacy uploads remain unmanaged.
- JPEG segments/PNG chunks (including CRC)/WebP RIFF structural checks only; compressed image data never decoded or recompressed on Relay. EXIF orientation is separate; PNG IDAT, JPEG scan and WebP image payload bytes retained. Browser must successfully decode sanitized source to generate its own <=1600px PNG preview before card creation.
- Header buttons in existing Codex and Agent headers open the same panel without changing workspace height. All transactions are online/memory-only; closing the panel preserves memory, closing/reloading the app loses unconfirmed state. No auto-reconnect of capture operations; explicit retry keeps frozen IDs/body and verifies storeId/read-back. 401 stops HTTP and capture ASR recovery.
- Native recorder is reused for voice capture on supported Android hosts; desktop browsers retain the existing unavailable notice. Raw ASR is separately immutable; capture has no refinement call and never writes a chat draft. W2b owns native shares/camera/inbox and offline persistence.
