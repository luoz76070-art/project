# Claude Code 接入设计

## 缺口与链路

现有Claude适配器、手机通道及0.1.2 Mods插件已交付；初期缺口为本机2.1.220版本不兼容、网关缺少Claude桥接配置、原宿主未加载模块。独立CLI接通后，用户明确要求与桌面原会话同步；最终由官方桌面自己的Code引擎加载插件，独立CLI不再作为默认入口。复用既有产品代码。

MobiCodex电脑页 → 原Broker/Tunnel → 原单网关ClaudeAdapter → 原Claude进程Mods → 用户选定的旧接口。模型凭证只进入Claude私有环境，不传手机或网关会话API。独立桥接密钥仅供本机鉴权，不复用手机或其他通道Token。

## 配置与运行

- 固定官方2.1.287核对registry SHA512，隔离HOME执行严格validate和8项官方无模型测试。通过后与用户旧CLI并存，加载固定mobile-claude目录。
- 用户最初选择cc，后指定cc1。最终以CC Switch的cc1为来源，提供商IDddc4915e-02b8-485f-b87a-25366b392944；同步至Code并经真实UI选中。该项完整接口与旧cc一致，最新Haiku/基础Sonnet真实响应已恢复200。保留原供应商数据、权限/Hooks/非接口字段及会话，配置变更前私有备份。默认选已验证的claude-sonnet-5-5，不沿用当前分组404的Medium。
- 原私有网关配置只增加claude.bridgeToken；先备份配置、设备状态、固定运行入口。现有bundle已支持接口，原则上只正常重启使配置生效，不升级其他通道。
- 桌面1.46388.4自带Code2.1.219，低于插件下限；完整私有备份后安装官方桌面4.23118.0及其manifest指定的Code2.1.317，核对官方SHA和签名。默认PATH CLI2.1.220保留。
- 通过官方插件安装器安装用户级mobile-codex-bridge@mobicodex-local，在native settings中仅增加两项桥接env。桌面原会话由其正常启动的Code进程登记，保留原会话ID，不复制历史或另开CLI替代。
- 私有start-claude.command改为正常打开/聚焦Claude.app；--check只读检查配置，不启动会话或请求模型。旧独立CLI入口与状态归档到私有回退目录，旧进程仅在确认idle后通过自有PTY正常/exit。

## 验证与回退

Mods只登记实际加载它的在线原进程，不能扫描或恢复未加载插件的历史。queue、任务绑定中断、原请求问答和单次审批沿既有能力，steer继续不可用。手机复用code10。

先隔离检查，再验证实际空闲宿主登记及本地/公网列表和有截止订阅；真实收发与无模型检查分开。官方317通过8项隔离测试，用户已真机确认双端同会话收发，最终36项本地/公网只读断言通过。桌面真实探测的Opus502与Sonnet成功分别保留，不声称所有模型均恢复。回退保留旧应用、完整数据和私有配置，不覆盖新版迁移后的凭证存储字段；原固定网关保持。

## 修改边界与自审

新增本任务三份计划和最终审计，更新工程入口及相关Claude文档；私有运行时、启动入口与配置放用户应用支持目录。如暴露产品缺陷，先记录复现和最小源码范围。该方案不改变模型协议、不复制会话、不新增Relay或远控UI；总整合59组保持原状态。
