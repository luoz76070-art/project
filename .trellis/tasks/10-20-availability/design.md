# C 设计

- Mac 输入按进程共用事务队列串行 focus→输入→确认，队列最多 16；helper 每请求独立 0700 目录、0600 文件，通过启动参数传递。helper 开始后的未知结果禁止自动降级重发。
- Mac App 监督 Relay/Tunnel，按进程对象隔离退出回调，指数退避重启，唤醒触发健康探测；状态区分进程/本地健康/公网可达，日志轮转且配置仅用户可读。自启脚本提供安装/卸载，不在开发中注册。
- 主 Token 仍为管理员恢复入口；一次性配对码有效 5 分钟，交换独立设备凭证，服务端仅存哈希，原子持久化到用户数据目录。管理员可撤销，立即关闭该设备 SSE，旧 stream token 同时失效。
- 请求鉴权在解析正文前完成；流和上传按设备及全局有界，日志不记录 query、Authorization、secret 或正文。
- Android 使用 Keystore AES/GCM 加密凭证；启动迁移既有明文，成功后删除明文。公网 Endpoint 要求 HTTPS，允许本机与私有 LAN 调试。保留手工配置和配对文本粘贴入口。
- 热更新先上传独立临时产物，远端校验 SHA/大小后原子切换 manifest；保留 previous.json 回滚。

源码实施/隔离检查阶段不部署；2026-10-20 用户另行明确授权公网连接修复，允许备份、TLS/续期、Broker 独立发布与 Mac App 切换，保留原凭证和回退点。仍不注册登录项、不调用真实输入或模型；通过临时目录、注入命令执行器、合成 HTTP 与原生编译检查验证。

权限反馈采用只读配置、正在运行的路径和目标 TCC 日志定位。当前 helper 是 Relay 直接启动的子进程，须核对 responsible app；空请求由开发工具启动时不能代表 Relay。授权操作由用户完成，真实发送由用户手动验收。修正文档中只要求 Input 授权的指引，不为诊断重建 App 或改签名，不改 TCC 数据库。长连接结论以心跳、空闲截止刷新、订阅前后台恢复和 Mac 监督源码及合成回归为依据，不宣称通过长时真机测试。
